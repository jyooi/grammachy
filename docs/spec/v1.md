# Grammachy v1 specification

Status: accepted on 2026-08-25.
Map: [HUF-170 Grammachy map: way to the v1 spec](https://linear.app/huffman/issue/HUF-170).
Glossary: [`CONTEXT.md`](../../CONTEXT.md).
Amended by [`evals.md`](evals.md) in sections 1, 4, 5.2, 6, 7, 10, 11, and 13.1.
Every numbered section is a normative contract and links the ticket that settled it.
The research reports under `.wayfinder/research/` hold the measurements behind each number.

## 1. Product

Grammachy is an Omarchy plugin that checks the grammar and spelling of text on demand.
The user highlights text in any application, presses SUPER + G, and a popup shows every Issue as a mark on the Selection.
The user Accepts or Skips each Fix, then Applies the Corrected text by clipboard or, opt in, by replacing the Selection.
Long text goes to the Compose window, opened by SUPER + SHIFT + G, which checks a Draft in Chunks.

Standing rules:

- The plugin never checks while the user types.
  Every Check is an explicit Trigger.
- v1 is offline by default.
  Text leaves the machine only with the opt in `openrouter` engine of section 4.
  That engine sends the text only to `openrouter.ai`, and only after the user gives consent.
  Every other engine keeps the text of a Check on the machine.
- Depth is grammar and spelling only.
  Style is never reported and the user's voice is kept.
- Target English is `en-US`.
  Explanations are in English.
- Plugin id is `io.github.jyooi.grammachy`.
  The manifest is publishable to the Omarchy plugin marketplace.

Out of scope for v1, by decision on the map: inline checking through fcitx5 or a browser extension, mistake history, dictation, custom style guides, personal dictionaries, target languages other than English, and every online engine other than the opt in `openrouter` engine of section 4.

## 2. Surfaces and triggers

Settled in [HUF-180 Compose window in v1](https://linear.app/huffman/issue/HUF-180) and [HUF-174 Panel prototype](https://linear.app/huffman/issue/HUF-174).

The manifest declares one plugin id with `kinds: ["bar-widget", "overlay"]` and `keepLoaded: true`.
The overlay hosts both surfaces through `open(payload)`:

| Payload | Surface |
|---|---|
| `{"mode": "quick"}` | The quick popup card of section 6. Captures the Selection, runs one Check, shows the marked text. |
| `{"mode": "compose"}` | The Compose card with the kept Draft. No capture. |
| `{"mode": "compose", "text": "..."}` | The Compose card with `text` as the new Draft. A non-empty existing Draft is replaced after a confirm. |

The bar widget is a click button that calls `shell.summon("io.github.jyooi.grammachy", "{\"mode\":\"quick\"}")`.
The shell routes `summon` to the overlay because a second kind is declared, so the popup QML lives in the overlay entry point, not in the bar widget file.

Triggers:

| Trigger | Opens |
|---|---|
| SUPER + G | quick popup |
| Bar widget click | quick popup |
| SUPER + SHIFT + G | Compose with the kept Draft |
| `Open in Compose` on the too-long card | Compose with the Selection as Draft |
| Compose button in the popup header | Compose with the current Selection as Draft, even under the limit |
| Omarchy menu entry `grammachy.compose` | Compose with the kept Draft |

Both hotkeys are `hl.unbind` plus `o.bind` pairs in `~/.config/hypr/bindings.lua` that run `omarchy-shell shell summon io.github.jyooi.grammachy '<payload>'`.
Lua is the file Omarchy loads: `hyprctl systeminfo` answers `configProvider: lua`, so the `.conf` files beside it are never read.
SUPER + SHIFT + G carries an Omarchy default, which is why the unbind comes first.
Section 10 says who writes them.

## 3. Capture

Settled at charting and in [HUF-172 Omarchy plugin contract](https://linear.app/huffman/issue/HUF-172); the fallback steps were settled in [HUF-178 Assemble the v1 spec](https://linear.app/huffman/issue/HUF-178).

Bar widgets receive no summon payload with the Selection, so the overlay captures it itself with Quickshell `Process` runs:

1. Run `wl-paste --primary --no-newline`.
   A non-empty result that is not only whitespace is the Selection.
2. Otherwise save the current clipboard with `wl-paste --no-newline`, run `wtype -M ctrl c -m ctrl`, wait 150 ms, and read `wl-paste --no-newline`.
   Restore the saved clipboard with `wl-copy` afterwards.
   A non-empty result is the Selection.
3. Otherwise show the `empty_selection` card from section 8.

`wtype` and `wl-clipboard` ship with Omarchy.
The capture never trims or normalises the text.
The exact bytes captured are the text every span in section 5 indexes into.

Before step 1 the overlay also reads `hyprctl activewindow -j` and keeps the address and the geometry it answers.
That is the **source window**: the window the Selection came from.
The popup window is still hidden at that moment, so the compositor still calls the source window the active one; once the popup shows, the answer is gone.
Nothing focused, for example the desktop, is no source window, and every step after that works without one.
Section 6 is what uses it.

## 4. Engines and lifecycle

Settled in [HUF-175 Default engine and its lifecycle](https://linear.app/huffman/issue/HUF-175), on the measurements of [HUF-171](https://linear.app/huffman/issue/HUF-171), [HUF-181](https://linear.app/huffman/issue/HUF-181), and [HUF-182](https://linear.app/huffman/issue/HUF-182).
Extended by [HUF-206](https://linear.app/huffman/issue/HUF-206) with the `openrouter` cloud engine.

| Slug | Role | Runs | Lifecycle | Timeout |
|---|---|---|---|---|
| `languagetool` | Default | LanguageTool 6.6 from pacman, `en-US`, `motherTongue` from the Native language setting | Transient user unit `grammachy-languagetool` on `127.0.0.1:8081`, started by the CLI with `systemd-run --user` when the port does not answer, stays up until logout | 10 s |
| `openai` | Opt in deep engine | Any OpenAI-compatible chat endpoint whose host is `localhost`, `127.0.0.1`, or `::1`. Recommended: Gemma-4-E4B-it Q4_K_M through llama.cpp, Apache-2.0 | Transient user unit `grammachy-llama` when the loopback port does not answer, with `--ctx-size 4096 --reasoning-budget 1024 --reasoning-budget-message "Answer now."` | 90 s |
| `harper` | Opt in, zero dependency | `harper-core` 2.8 in process, loaded only when selected | In process | 10 s |
| `openrouter` | Opt in cloud engine | Any model on OpenRouter, chosen by id. Recommended: the cloud line of the current benchmark file | None. The request goes to `https://openrouter.ai/api/v1` over TLS | 30 s |

Rules:

- One engine per Check.
  There is no automatic fallback.
  An unreachable engine answers `engine_unavailable` and the user switches engine in Settings.
- Any other slug is `bad_arguments`.
- The `openai` base URL host must be `localhost`, `127.0.0.1`, or `::1` in v1.
  Any other host is `bad_arguments`, and the CLI makes no request.
- No non-commercial model weights ship or are recommended.
  The slugs `gector`, `coedit`, and `hybrid` are reserved.
- The Check size limit belongs to the Engine: 2,000 UTF-16 code units for `openai`, 5,000 for `languagetool`, `harper`, and `openrouter`.
  LanguageTool `maxTextLength` stays 5000.
- The `languagetool` unit is started with the LanguageTool HTTP server from the pacman package on port 8081, `maxTextLength` 5000, and no external access.
  The implementation reads the exact server command from the installed package.
- The `openai` request sends `max_tokens` 2048, which is 1,024 tokens for thinking and 1,024 tokens for the answer.
  Thinking is on by default and the `localThinking` setting of section 7 turns it off per request through `chat_template_kwargs.enable_thinking`.
  A change of that setting needs no unit restart.
- `openrouter` is the one engine that sends the text of a Check off the machine, and only to `openrouter.ai`.
  It reuses the `openai` request, prompt, and mapping on the constant endpoint `https://openrouter.ai/api/v1/chat/completions`, and it has no base URL setting.
  No other slug sends a request off the machine, and the loopback rule for `openai` is untouched.
  TLS lives in the binary through `ureq` with `rustls`.
- `openrouter` needs a key in `~/.config/grammachy/openrouter-key`, mode 0600, written by `grammachy setup --openrouter-key`.
  The key is never stored in `shell.json` and never reaches QML.
- The first Check with `openrouter` shows the consent card.
  Continue stores `cloudConsent` and Cancel sends nothing.
- `openrouter` is never the default engine.
- Hardware tiers affect only the install step: `grammachy doctor` names the llama.cpp Vulkan or CPU package for the machine.
  `doctor` checks `ggml-cpu` plus one backend package, which is `ggml-vulkan` on the GPU tier and nothing more on the CPU tier, not only `/usr/bin/llama-server`.
  NPU use is a documented manual FastFlowLM setup reached through the `openai` adapter.

Honest cost, stated to the user in the README: the default catches about one third of native-language interference errors with zero false positives in about 20 ms and 0.7 GB.
The opt in LLM catches nearly all of them, needs about 8 GB free, and takes seconds.

Native language mapping for `languagetool`:

| Setting | `motherTongue` sent |
|---|---|
| `none`, `ms` | nothing |
| `zh` | `zh-CN` |
| `ja` | `ja-JP` |
| `es`, `fr`, `de`, `pt` | the same code |

The `openai` prompt, which `openrouter` reuses, names the native language for every value but `none`.
`harper` ignores it.

## 5. Issue contract between the CLI and the shell

Settled in [HUF-173 Issue JSON contract](https://linear.app/huffman/issue/HUF-173) and extended by [HUF-180](https://linear.app/huffman/issue/HUF-180) and [HUF-184](https://linear.app/huffman/issue/HUF-184).

### 5.1 `grammachy check`

```
printf %s "$TEXT" | grammachy check [--native <code>] [--target en-US] [--engine <slug>]
```

- stdin is the raw UTF-8 text, verbatim.
- `--native` is one of `zh`, `ms`, `es`, `fr`, `de`, `pt`, `ja`.
  Omitted uses the stored entry, then the default `none`.
- Flags win over the Settings entry in `shell.json`, which wins over built-in defaults (section 7).
- stdout is exactly one JSON object.
  stderr is logs only and is never parsed.
- Exit 0 for any result, including zero Issues.
  Exit 1 for an error envelope.

Result envelope:

```json
{
  "contractVersion": 1,
  "engine": "languagetool",
  "elapsedMs": 23,
  "issues": [
    {
      "start": 17,
      "end": 21,
      "original": "book",
      "fix": "books",
      "reason": "Possible agreement error. The noun 'book' seems to be countable.",
      "category": "grammar",
      "ruleId": "CD_NN"
    }
  ]
}
```

Issue fields:

- `start`, `end`: UTF-16 code units, half open, indexed into the exact stdin text.
- `original`: the text slice.
  The shell verifies `text.slice(start, end) === original` and drops a mismatch with a stderr warning.
- `fix`: one replacement string, the engine's first suggestion.
- `reason`: one English sentence with no rule id.
- `category`: `grammar` or `spelling`.
- `ruleId`: optional engine-specific string for bug reports.
- No `severity`, no `id`.
  The array index is the identity within one Check.

Guarantees the CLI gives: Issues are sorted by `start`, never overlap (the earlier one wins), never have `fix` equal to `original`, and never lack a fix.

Error envelope:

```json
{ "contractVersion": 1, "error": { "code": "engine_unavailable", "message": "LanguageTool did not answer on 127.0.0.1:8081" } }
```

Codes: `empty_selection`, `text_too_long`, `engine_unavailable`, `engine_timeout`, `engine_error`, `bad_arguments`.
The shell treats an unknown code as `engine_error`, a missing or mismatched `contractVersion` as an error state, and no JSON on stdout as the `bad_arguments` card.

### 5.2 `grammachy chunk`

```
printf %s "$DRAFT" | grammachy chunk [--engine <slug>]
```

stdout: `{"contractVersion": 1, "chunks": [{"start": 0, "end": 4812}, ...]}` in UTF-16 units, non-overlapping, covering the whole text.

`--engine` names the Engine whose Check size limit the Chunks are packed to.
Omitted, it resolves the way `check` does: the stored entry, then the default of section 7.

Splitting: pack whole paragraphs (blank-line separated) greedily up to the selected engine's Check size limit.
A paragraph over the limit splits at sentence ends: `.`, `?`, `!`, or a closing quote after one, followed by whitespace.
A sentence over the limit is a hard cut at the limit.
Text over 50,000 units answers `text_too_long`.
An empty Draft answers `empty_selection`.

### 5.3 Corrected text

The shell splices in JavaScript, last to first, in `ui/splice.js`:

```
out = text
for i from issues.length - 1 down to 0:
  if accepted[i]: out = out.slice(0, issues[i].start) + issues[i].fix + out.slice(issues[i].end)
```

There is no `apply` subcommand.

## 6. Quick popup

Settled in [HUF-174 Panel prototype](https://linear.app/huffman/issue/HUF-174), variant B "marked text".
The prototype is `.lavish/huf-174-panel-prototype.html`.

- Card about 680 px wide, `PopupCard` chrome, theme `[controls]` tokens.
- The card opens beside the source window of section 3: at that window's top edge, on its trailing side.
  With no room on the trailing side it takes the leading side, and with room on neither it sits inside the window, held to that window's own trailing edge.
  Whatever comes out is clamped into the monitor less the bar and one gap, so no bar position and no window put the card off the screen.
  With no source window on this monitor the card hangs from the bar widget's own corner, under the bar, which is where it always hung.
- Hero: title, meta line `N issues, K accepted, <engine>, <elapsedMs> ms`, the auto-replace toggle on the trailing edge, a Compose button, and a gear that flips to the Settings view.
- Body: the whole Selection with paragraphs preserved.
  Each Issue is an underlined mark: solid for grammar, dotted for spelling.
  An accepted mark shows the Fix in green, a skipped mark stays dim, the focused mark has the selection background.
  The text region scrolls inside the card and the card never grows past the screen.
- Inspector strip: original, fix, category, reason for the focused Issue, with Accept and Skip.
- Footer: counts (accepted, skipped, open), `Accept all open`, and the Apply button.
- Keys: Enter accept, Space skip, Up and Down move focus, A accept all, Esc close, Ctrl + C copy, Ctrl + Enter replace.
  Accept and Skip advance focus to the next open Issue.
- Empty state: check mark, `No issues found`, `<chars> characters checked, <engine>, <ms> ms`, Close.
- Too-long card (`text_too_long`): a size bar of limit against selected, the message, Close, `Check the first N only`, and the primary `Open in Compose`.
  The card fires at the selected engine's Check size limit, not at one fixed number.

### Apply

Settled at charting and in [HUF-178](https://linear.app/huffman/issue/HUF-178).

| `autoReplace` | Button | Action |
|---|---|---|
| off | `Copy corrected text`, then `Copied` | `wl-copy` the Corrected text. |
| on | `Replace selection`, then `Replaced` | `wl-copy` the Corrected text, close the popup, ask the compositor for the source window by address, and only once `hyprctl activewindow -j` names it, `wtype -M ctrl v -m ctrl`. The Corrected text stays in the clipboard. |

Apply is disabled until one Issue is accepted.
Replace only works while the Selection is still highlighted in the source window, and the Settings hint says so: "Replaces the highlighted text by pasting over it".

Closing the popup hands the keyboard to whatever the compositor picks, which is not the source window whenever another window sits under the card.
The ask is what makes Replace land in the right place, and the dispatch alone is not enough: it succeeds for a window that is gone, so the check against `activewindow` is what lets the keystroke out.
A source window that has closed is a notice, "The source window closed", and no keystroke anywhere; the Corrected text is on the clipboard.

## 7. Settings

Settled in [HUF-179 Settings UI and storage](https://linear.app/huffman/issue/HUF-179) and [HUF-184 Native language list](https://linear.app/huffman/issue/HUF-184).

Storage is the plugin's entry in `~/.config/omarchy/shell.json`, written from the overlay with `shell.updateEntryInline` and read reactively through `setting(name, fallback)`.
There is no own config file and no `config` subcommand.
`omarchy-shell shell setBarWidget io.github.jyooi.grammachy <key> <valueJson>` covers scripting.

| Key | Values | Default | Control |
|---|---|---|---|
| `nativeLanguage` | `none`, `zh`, `ms`, `es`, `fr`, `de`, `pt`, `ja` | `none` | Dropdown, in that order |
| `targetEnglish` | `en-US` | `en-US` | File only |
| `engine` | `languagetool`, `openai`, `harper`, `openrouter` | `languagetool` | Dropdown labelled LanguageTool, Local LLM, Harper, Cloud LLM (OpenRouter) |
| `autoReplace` | boolean | `false` | Toggle, also in the popup hero |
| `openaiBaseUrl` | string | `http://127.0.0.1:8080` | Text field, shown when engine is `openai` |
| `openaiModel` | string | `gemma-4-e4b-it` | Text field, shown when engine is `openai` |
| `openaiApiKey` | string | `""` | File only |
| `localThinking` | boolean | `true` | Toggle, shown when engine is `openai` |
| `openrouterModel` | string | `""`, placeholder `google/gemini-3.7-flash` | Text field, shown when engine is `openrouter` |
| `cloudConsent` | boolean | `false` | File only |

Rules:

- The gear in the popup header flips the card to the Settings view; the check view stays clean.
- Persist on change, no Save button.
  A change applies to the next Check, and Issues on screen stay.
- An unknown stored value reads as the default and shows the default selected.
  Nothing is rewritten until the user changes it.
- The manifest keeps `schema` and `defaults` as documentation.
  The shell stores them and never renders or merges them, so the overlay never relies on `defaults`.
- The CLI reads flags first, then this entry in `shell.json`, then built-in defaults.
  A missing file is fine.
- The `--thinking on|off` flag of `grammachy bench` wins over `localThinking`.
- An empty `openrouterModel` answers `bad_arguments`.
  The placeholder names the recommended cloud model of the current benchmark file.
- Only the consent card writes `cloudConsent`.
  The Settings view never shows it, and the OpenRouter key never lands in this file.

## 8. Error cards

Settled in [HUF-178](https://linear.app/huffman/issue/HUF-178), with `text_too_long` from [HUF-174](https://linear.app/huffman/issue/HUF-174) and per-Chunk failure from [HUF-180](https://linear.app/huffman/issue/HUF-180).

`<Engine>` is the display name of the current engine setting.
When the CLI sent a message, it shows under the body in monospace.

| Code | Title | Body | Buttons |
|---|---|---|---|
| `empty_selection` | Nothing selected | Highlight some text, then press SUPER + G. | Close, Open Compose |
| `engine_unavailable` | `<Engine>` is not running | Grammachy could not reach it on this machine. Then the `doctor` one-line diagnosis. | Close, Retry, Settings |
| `engine_timeout` | `<Engine>` took too long | No answer within `<timeout>` s. A first start can take a moment. | Close, Retry, Settings |
| `engine_error` | `<Engine>` returned an error | The Check did not finish. | Close, Retry, Settings |
| `bad_arguments`, no JSON | Grammachy could not run the check | The companion tool is missing or out of date. | Close, Setup |
| `text_too_long` | see section 6 | | Close, Check the first N only, Open in Compose |

Retry re-runs the Check with the same Selection and no re-capture.
Settings opens the Settings view of the same card.
Setup opens the setup card from section 9.

## 9. Compose window

Settled in [HUF-180 Compose window in v1](https://linear.app/huffman/issue/HUF-180).

- Centered card about 900 px wide and 80 percent of screen height, dimmed backdrop, `PopupCard` chrome.
  Compose uses the same inspector, footer, and keys as the popup.
  It uses the same hero without the auto-replace toggle.
- Two modes.
  Edit mode is a plain text area holding the Draft.
  Check switches to review mode with the marked text, inspector, and footer, the text region scrolling.
  Back to edit returns the Corrected text as the new Draft.
- Check runs on demand only: a Check button in the footer and Ctrl + Enter.
- Chunked checking: run `grammachy chunk`, then `grammachy check` once per Chunk in sequence, adding the Chunk `start` to every Issue span.
  The hero meta line reads `Checking k of n, <engine>, <elapsed>` with a Cancel button.
  A failed Chunk keeps the Issues from finished Chunks, shows the error inline with the engine message, and offers `Retry remaining` and `Review what we have`.
  `Retry remaining` resumes at the failed Chunk.
  A reader who picks an Engine of another Check size limit at the failure gets a new Chunk list instead, and the run restarts.
- Apply is `Copy corrected text` only.
  Auto-replace never applies in Compose.
- The Draft stays in memory while the shell runs.
  A Clear button empties it.
  Nothing is written to disk.
- Cap 50,000 UTF-16 units; over it Compose refuses the Check with the count and the cap.
- Esc in edit mode closes and keeps the Draft.
  Esc in review mode returns to edit mode with the Corrected text, as Back to edit does.
  A backdrop click closes.

## 10. Companion CLI, packaging, and setup

Settled in [HUF-176 Companion CLI stack and packaging](https://linear.app/huffman/issue/HUF-176), recorded as [ADR 0001](../adr/0001-cli-in-rust-shipped-as-release-binary.md), with the setup steps from [HUF-178](https://linear.app/huffman/issue/HUF-178).

- Rust, one static binary about 13 MB: `harper-core`, blocking `ureq`, `clap`, `serde_json`, opt-level z, LTO, stripped.
  No async runtime.
- The overlay runs `Qt.resolvedUrl("bin/grammachy")` through a Quickshell `Process` with the text on stdin.
  No PATH assumption.
- CI builds `grammachy-x86_64-linux` on every tag.
  `cli.lock` pins version and sha256.
  `bin/bootstrap.sh` (curl, sha256sum, chmod) fetches it into the gitignored `bin/grammachy`.
  Nothing downloads without a click.
  Developers `cargo build --release` and copy.
- Manifest version equals crate version.
  A release is two commits: the tag CI builds, then the `cli.lock` bump.
- Subcommands: `check`, `chunk`, `bench`, `doctor`, `setup`, `setup --openrouter-key`, `setup --remove`.

Setup card: when `bin/grammachy` is missing, the overlay shows a card naming the download and the pinned hash with an Install button that runs `bin/bootstrap.sh` and streams its output.

`grammachy doctor` checks the binary, LanguageTool, llama.cpp, the model file, and the units, and prints the exact `sudo pacman -S ...` or AUR line for anything missing.
pacman steps stay manual.

`grammachy setup` does the non-sudo parts, idempotently.
It writes the hotkeys and the menu entry first, then it fetches the model.

1. An idempotent block in `~/.config/hypr/bindings.lua` between `-- grammachy begin` and `-- grammachy end`.
   The block holds the two bindings from section 2.
   Then the command runs `hyprctl reload`.
   A missing compositor does not fail the run.
   The block is on disk and the next Hyprland start reads it.
2. The `grammachy.compose` entry in `~/.config/omarchy/extensions/omarchy-menu.jsonc`.
   The row sets `"parent": "root"` so a user can select it.
3. A model download to `~/.local/share/grammachy/models/` when the engine is `openai`.
   The command skips this step when the engine is not `openai`.
   The command also skips this step when the file is present.

Hardware tiers name the llama.cpp backend package only (section 4).
The weights file is the same on every tier.
The default file is `gemma-4-E4B-it-Q4_K_M.gguf` from `unsloth/gemma-4-E4B-it-GGUF`.
The catalogue pins that file by sha256, as `cli.lock` pins the CLI binary.
A failed model step keeps the hotkeys and the menu entry.

`printf '%s' "$KEY" | grammachy setup --openrouter-key` writes the OpenRouter key of section 4.
It creates `~/.config/grammachy/` with mode 0700 and writes `openrouter-key` with mode 0600.
The key never lands in `shell.json`.

`grammachy setup --remove` reverses steps 1 and 2, and it deletes `~/.config/grammachy/openrouter-key`.
The model stays.

The command prints one JSON envelope on stdout.
Exit 0 carries a report with `mode` and `steps`.
Exit 1 carries an error envelope with code `setup_failed`.
A Check never answers `setup_failed`.

systemd: transient units only, through `systemd-run --user --unit grammachy-languagetool ...` and `grammachy-llama`.
No unit files are installed, so plugin removal leaves nothing behind.

## 12. Install steps

1. `omarchy plugin add <repo url>`.
   This is a plain clone plus `omarchy-plugin-validate`; nothing else runs.
2. Click the Grammachy bar widget.
   The setup card names the pinned binary; click Install.
3. The popup's `engine_unavailable` card shows the `doctor` line.
   Run the `sudo pacman -S languagetool` line it prints.
4. Run `bin/grammachy setup` from the plugin folder to install the hotkeys and the menu entry.
   The hotkeys land in `~/.config/hypr/bindings.lua` and `grammachy setup --remove` takes them out again.
5. Optional deep engine: set the engine to Local LLM in Settings, run the `doctor` line for llama.cpp, then `bin/grammachy setup` for the model download.

## 13. Test plan

Settled in [HUF-176](https://linear.app/huffman/issue/HUF-176) and [HUF-178](https://linear.app/huffman/issue/HUF-178).

CI on every push runs `cargo test`, `cargo clippy -- -D warnings`, and `cargo fmt --check`.
CI lints every QML file with `qmllint -I /usr/share/omarchy/shell` and validates the manifest with `omarchy-plugin-validate`.
Node runs the `splice.js`, `tokens.js`, `settings.js`, `keymap.js`, `format.js`, `errors.js`, and `anchor.js` tests.

Rust unit tests: envelope serialisation; UTF-16 span math including surrogate pairs and CRLF; overlap dropping; adapter mapping per engine from recorded engine responses; Chunk splitting at paragraph, sentence, and hard cut; settings precedence of flags, then `shell.json`, then defaults; `doctor` output per missing piece.
A Rust test keeps the Check limit and Draft cap in QML equal to the CLI.
A Rust test keeps the overlay timeout copy equal to each adapter timeout.
Live LanguageTool tests skip unless `127.0.0.1:8081` answers.
Live `openai` tests skip unless `127.0.0.1:8080` answers.
Every benchmark metric has a unit test that runs from recorded answers, so no test needs a live model.
No test reaches `openrouter` or spends cloud credit.
The interference sentences are a fixture that prints the catch rate, not a gate.

Manual smoke checklist, run before every tag:

1. Hotkey on a primary selection in a terminal.
2. Hotkey on an Electron text field, which exercises the Ctrl + C fallback.
3. Hotkey with nothing selected, which shows the `empty_selection` card.
4. A 6,000 unit selection, which shows the too-long card and hands off to Compose.
5. A 20,000 unit Draft in Compose, with progress and Cancel.
6. Stop the LanguageTool unit, Check, see the `engine_unavailable` card, Retry after the unit starts.
7. Switch to Harper, Check, switch back.
8. Auto-replace on in a terminal and in a browser field.
9. Settings persist across a shell restart.
10. Fresh clone install from the README on a second user account.

### 13.1 Benchmark

Settled in [HUF-178](https://linear.app/huffman/issue/HUF-178) and replaced by [`evals.md`](evals.md) for the sets, the metrics, the tables, the `bench` flags, and the recommendation rules.

- Regression rule: a release must not drop the default engine's catch rate or raise its false positives against the previous file.
- The fixture grows only through real user sentences, at least 10 per native language before a language is called covered.
- Results are committed as `docs/benchmarks/<version>.md` on every tag and whenever an engine, adapter, or L1 rule pack changes.
- Everything else about the benchmark is fixed by [`evals.md`](evals.md).

## 14. Milestones

Each milestone is one implementation session and one PR on `main`, in this order.

1. **CLI check.** `grammachy check` with the `languagetool` adapter, the envelope, the unit start, the settings read, and the Rust tests.
   Done when the fixture prints a catch rate against a live LanguageTool.
2. **Quick popup.** Manifest, bar widget, overlay with `quick` mode, capture with the fallback, marked text, inspector, footer, keys, empty and too-long cards, both Apply paths, `splice.js` and its tests.
   Done when smoke items 1 to 4 and 8 pass with a hand-copied binary.

   Done when smoke items 6, 7, 9, and 10 pass from a tagged release.
4. **Compose.** `grammachy chunk`, `compose` mode, edit and review, chunk loop with progress and failure handling, the four Compose triggers.
   Done when smoke item 5 passes.
